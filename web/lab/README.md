# MAAI ラボ：カメラ映像から充電部を AR 表示（実験）

本線（main）にも `ar-prototype` にも入れない実験ブランチ `lab-camera-ar`。
MAAI の設計原則のうち次の3つを、試すためにあえて外している。

- 本線は「カメラで充電部を当てない（包絡は図面と開閉器の状態から計算）」。ここではカメラ映像から充電部の**候補**を探す。電気が来ているかは映像では分からないので、充電中か停止中かは人が決める。
- 本線は「外部 API への送信は `agent/client.py` の一箇所から、マスクを通して記録する」。ここでは端末のブラウザから Anthropic API を直接呼ぶ（マスクも `logs/outbound/` の記録もない）。
- 本線は「離隔の値と距離は `engine/` の決定論コードだけが決める」。ここでは離隔の目安値（本線の離隔表 default-jp を写した値。このブランチの `data/tables/clearance.csv` は分岐前の古い版で値が違う）と距離を、ブラウザの中で計算する。どれも参考値。

## データの流れ

- カメラ映像は端末の中だけで使う。「候補を探す」を押したときだけ、その1コマを Anthropic の API に送る。
- リポジトリにも GitHub Pages にも、撮った内容は残らない（静的なページで、書き込む先がない）。
- 送った1コマは Anthropic の扱い（保存の方針）に従う。実在の設備で撮るときは、撮影してよい場所かを先に確かめる。
- API キーは画面で入れる。「このタブを閉じるまで覚える」を選んだときだけ、そのタブの間ブラウザに残る（sessionStorage）。Pages の localStorage は同じアカウントの全リポジトリのページで共有されるので、キーは置かない。利用上限を絞った実験専用のキーを使う。
- ページが読み込むコードは、リポジトリに同梱したもの（three.js）だけ。キーを扱うので、改ざん照合のない CDN のコードは読まない。
- 撮った写真・画面録画をこのリポジトリにコミットしない（公開リポジトリ。CLAUDE.md の制約）。

## 開き方

GitHub Pages の配信ブランチを `lab-camera-ar` にして、Android の Chrome で `web/lab/camera-ar.html` を開く。
（`lab-camera-ar` は `ar-prototype` から分けたので、`web/ar.html` もそのまま開ける）
