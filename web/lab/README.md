# MAAI ラボ：カメラ映像から充電部を AR 表示（実験）

本線（main）にも `ar-prototype` にも入れない実験ブランチ `lab-camera-ar`。
MAAI の設計原則のうち次の4つを、試すためにあえて外している。

- 本線は「カメラで充電部を当てない（包絡は図面と開閉器の状態から計算）」。ここではカメラ映像から充電部の**候補**を探す。電気が来ているかは映像では分からないので、充電中か停止中かは人が決める。
- 本線は「外部 API への送信は `agent/client.py` の一箇所から、マスクを通して記録する」。ここでは端末のブラウザから Anthropic API を直接呼ぶ（マスクも `logs/outbound/` の記録もない）。
- 本線は「Claude の提案は `engine/` で再検証してから表示する」。ここでは Claude の意見（番号の物が充電部になりうるか）を検証せずに一覧に添える。意見は状態も離隔帯も変えず、充電中か停止中かは人が決める。
- 本線は「離隔の値と距離は `engine/` の決定論コードだけが決める」。ここでは離隔の目安値（本線の離隔表 default-jp を写した値。このブランチの `data/tables/clearance.csv` は分岐前の古い版で値が違う）と距離を、ブラウザの中で計算する。どれも参考値。

## データの流れ

- カメラ映像は端末の中だけで使う。「候補を探す」を押したときだけ、その1コマを Anthropic の API に送る。
- リポジトリにも GitHub Pages にも、撮った内容は残らない（静的なページで、書き込む先がない）。
- 送った1コマは Anthropic の扱い（保存の方針）に従う。実在の設備で撮るときは、撮影してよい場所かを先に確かめる。
- API キーは画面で入れる。「このタブを閉じるまで覚える」を選んだときだけ、そのタブの間ブラウザに残る（sessionStorage）。Pages の localStorage は同じアカウントの全リポジトリのページで共有されるので、キーは置かない。利用上限を絞った実験専用のキーを使う。
- ページが読み込むコードは、リポジトリに同梱したもの（three.js）と、ハッシュで照合した onnxruntime-web だけ。キーを扱うので、改ざん照合のない CDN のコードは読まない。
- 端末内の検出器（任意）は、画像を端末の外に出さない。onnxruntime-web 1.20.1 は jsDelivr から取り、ハッシュ（SRI）が合ったものだけをワーカーの中で動かす（ワーカーからはキーに触れられない）。ハッシュは Actions の `ort` job が npm の配布物から計算したもの。
- 検出器のモデル（YOLO-World、AGPL-3.0）はリポジトリにも Pages にも置かない。利用者が端末に落として選び、そのブラウザの IndexedDB にだけ残る（開始画面の「消す」で消える）。
- 撮った写真・画面録画をこのリポジトリにコミットしない（公開リポジトリ。CLAUDE.md の制約）。

## 開き方

GitHub Pages の配信ブランチを `lab-camera-ar` にして、Android の Chrome で `web/lab/camera-ar.html` を開く。
（`lab-camera-ar` は `ar-prototype` から分けたので、`web/ar.html` もそのまま開ける）

## 検出器のモデルを端末に入れる

1. GitHub の Actions → `lab-yoloworld-export` の成功した実行 → Artifacts の `yoloworld-onnx` を落とす（GitHub にログインが要る。保存は30日）。
2. zip を開き、`yoloworld-s.onnx`（約48MB）を端末に置く。中の `LICENSE-NOTE.txt` と `LICENSE-AGPL-3.0.txt` が許諾と対応ソースの在り処。
3. `web/lab/detector-check.html` で「モデルを選ぶ」→ 写真を選んで「検出する」。枠が出れば動いている。選んだモデルは `camera-ar.html` でも使える。

## 変電所機器の検出器（公開データで学習）

YOLO-World（語を指定するだけの検出器）は、変電所の機器を言葉として知らず、広く写した写真では枠が出なかった。そこで公開データだけで検出器を学習する（Actions の `lab-substation-train`）。

- データ: A Semantically Annotated 15-Class Ground Truth Dataset for Substation Equipment（Zenodo 7884270、CC BY 4.0）。ブラジルの配電用変電所1か所を約2年撮った1,660枚、15種類（断路器の開閉と形式、遮断器、がいし2種、ケーブルヘッド、避雷器、リクローザ、変圧器・変流器・計器用変圧器）。Actions の中でだけ使い、リポジトリにも成果物にも入れない。
- 出発点を変えた2つを同時に学習して比べる。`oiv7` は Open Images V7 で学習済みの YOLOv8n から（公開元の表示では画像 CC BY 2.0・注釈 CC BY 4.0。ただしその重みを COCO から始めたかは記載がなく不明）。`scratch` は事前学習なしで、使うデータは CC BY 4.0 のこのデータだけ。
- できるモデルは Ultralytics の AGPL-3.0 で、成果物に許諾書の全文・対応ソース・データの出典を添える。MAAI 本体には入れない。
- 結果（CPU 4.2 時間）: `oiv7` は 61 エポックで mAP50 0.53（適合率 0.69、再現率 0.48）、`scratch` は 38 エポックで 0.22（0.49、0.20）。ゼロからでは学習量が足りない。`oiv7` の種類別 AP50 は、閉じたブレード断路器 0.79・変圧器 0.76・ヒューズ付き断路器 0.70・リクローザ 0.70 が高く、開いたブレード断路器 0.08（学習の枠が 284 と少ない）・開いたタンデム断路器 0.28・ケーブルヘッド 0.38 が低い。
- 確認用の画像は学習用と同じ変電所・近い時期の写真なので、数値は甘めに出る。確認用でも半分ほどを見逃し、見逃した物には離隔帯が出ない。日本の設備での当たり外れは点検ページで確かめる。
- 端末の onnxruntime-web（WASM）で同じ画像を検出し、Ultralytics の結果と一致することを Actions で確かめた。
- 使い方: Actions の `lab-substation-train` の実行ページから成果物 `substation-oiv7`（zip、約11MB、30日で消える）を落として開き、`substation-oiv7.onnx` を点検ページの「モデルを選ぶ」で選ぶ。探す語は変電所の15種類に自動で切り替わる。端末に保存できるモデルは1つなので、YOLO-World に戻すときは `yoloworld-s.onnx` を選び直す。

## 段階

1. Claude が1コマから候補を示す → 人が選んで照準で2回狙う → 3D の点 → 離隔帯を表示。
2. 端末内の検出器（いま）: がいし・ブッシング・架空線・断路器・遮断器・変圧器、近づく物（クレーン・ブーム・高所作業車・人）を見つけ続けて追跡する。横へ歩くと視線が増え、3視点・開き 3° 以上・奥行きの不確かさ ±4 m 以下で3Dになる（それまでは「歩くと3D」の枠だけ）。充電部になりうる物は既定で充電中にして、物の大きさと奥行きの不確かさを足した離隔帯を出す（歩くほど締まる）。近づく物には離隔帯までの距離を出す。「候補を探す」では、見つけた物に番号を付けた1コマを Claude に見せ、どれが充電部らしいかの意見をもらう（採否は人）。

### 検出器の注意

- 3D の位置は「物が止まっている」前提で、歩いた分の視線の交わりから求める。動く物（クレーン・ブーム・高所作業車・人）は直近6秒の視線だけで求め、いま見えているときだけ距離を出す（「目安」と表示）。物が動いている間は誤差が大きい。見えなくなると消える。
- 「誤検出として外す」（2回押し）は、その物を離隔帯と距離の計算から外す。外した数はチップと一覧に出し、写す表にも「誤検出として外した」と残す。「すべて戻す」で戻る。
- 写真で枠が出ないときは、点検ページで「確からしさの下限」を下げる・「細かく見る」（6分割）を試し、「種類ごとの最高」の値を見る。AR の下限は開始画面で選べる（下げると自信の低い物も追い、充電部になりうる物は充電中が既定なので帯が増える側に倒れる）。
- モデルの探す語（付帯情報の names）が画面の語と同じ順で同じでなければ、そのモデルは使わない（違うモデルだと、がいしを「人」と読み違えて離隔帯が出ないことがある）。

## 確かめ方

- `node web/lab/tests/detector.test.mjs`: 前処理・後処理、画素⇔視線、多視点の3D化、追跡（歩きながら首を振っても番号が変わらない）。
- Actions の `check` job: 書き出したモデルを点検ページ（headless Chromium）で動かし、見本画像の検出を Ultralytics の結果と照合する（onnxruntime-web は本番と同じく jsDelivr からハッシュ照合つき）。ページが外へ出した要求を全部記録し、照合済みの2ファイル以外への要求があれば失敗にする。探す語の一致も確かめる。
