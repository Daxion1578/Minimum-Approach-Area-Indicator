# スライド型の報告

本人は資料をスライドで読み慣れている。要点を絞り、1枚で1つのことだけを言う。

## 出力
- `reports/YYYY-MM-DD-<短い英語スラッグ>.html` に1ファイルで書く（`reports/` はコミットしない）。
- 外部の CSS・JS・フォントを読み込まない。画像は使わず、図は HTML/CSS か inline SVG で描く。
- ターミナルには、結論1行・要点2行・ファイルのパスだけを出す。Windows では `start reports\<ファイル名>` で開けると添える。

## 構成（最大5枚。不要な枚は省く）
1. **結論** — 1文と状態の札（完了／一部完了／詰まっている）。
2. **やったこと** — 3項目まで。各項目は1行。触ったフォルダ名を添える。
3. **確かめた結果** — テストの件数と結果、手元確認の合否。数字で示す。失敗があれば隠さず赤で。
4. **判断してほしいこと** — 選択肢を2〜3個並べ、推奨に印。それぞれ1行の理由と、選んだ場合の影響（時間・削る機能）。無ければこの枚は出さない。
5. **次の一手** — 次にやること1〜3個と、`docs/spec.md` §14 の日割りに対する遅れ・前倒し。

## 見た目
- 各スライドは 16:9 の枠（幅 960px、高さ 540px）を縦に並べる。白地、本文 20px 以上、見出し 32px、1枚あたり本文は40字×6行まで。
- 色は意味にだけ使う（緑=通った、赤=失敗・危険、黄=要判断）。装飾の色やグラデーションは使わない。
- 専門用語は初出に一言の説明を括弧で添える。
- 社名・設備名など公開してはいけない語は報告にも書かない。
