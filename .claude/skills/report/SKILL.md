# STATUS.md による報告

本人はスマホの GitHub で STATUS.md を見る。1ページで、上から読んで30秒で状況が分かるようにする。古い内容は残さず上書きする（履歴は git に残る）。STATUS.md は公開されるので、公開してよいことだけを書く。

## 構成（この順、見出しもこのまま）
1. `# 進み具合` — Mermaid の `gantt` で `docs/spec.md` §14 の日割りを描き、完了は `done`、作業中は `active`、遅れは `crit` を付ける。その下に「更新: 日付 時刻」を1行。
2. `## 結論` — 1文と状態（完了／一部完了／詰まっている）。
3. `## 確かめた結果` — テストの件数と結果、手元確認の合否を数字で。失敗は隠さない。画面があれば `docs/img/` のスクリーンショットを1枚だけ貼る（合成データしか映っていないことを確認してから）。
4. `## 判断してほしいこと` — 選択肢を2〜3個の表にし、推奨に「推奨」と書く。各行に理由1行と影響（時間・削る機能）。無ければ「なし」。
5. `## 次の一手` — 1〜3個。

## 書き方
- 本文は全体で40行以内。1項目1行。専門用語は初出で括弧書きの説明を添える。
- 社名・設備名など公開してはいけない語は書かない。
- 書き終えたら `python scripts/public_safety_check.py --staged` を通してからコミットする（メッセージ「状況: <結論の要約>」）。push は本人の確認を取ってから。
- ターミナルには結論1行と「STATUS.md を更新しました」だけを出す。
