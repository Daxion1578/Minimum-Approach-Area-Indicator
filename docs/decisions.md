## 2026-11-02

- **本質の再定義（仮）。** 本質は工程表でも配置でもなく、二つが重なる「停止の段階ごとに変わる近づけない領域」。さらに、クレーンの位置は機器の据付・搬入・仮置き・撤去と一体で決まるため、核は「工事で動くすべてのものに、その段階でその空間が使えるかを答える基盤」とした。クレーンは最初の問いにすぎず、搬入経路などは「やらないこと」から「同じ基盤に足せる問い」に位置づけを変えた。
- **使う人を一つに絞る（仮）。** 仕様では電力会社側・工事会社側の両方を挙げて主語がぼやけていた。工事会社の相談を受けて確認する側（停止範囲は決まったものとして受け取る）を主にした。停止範囲を入力ではなく計算結果として扱う設計は、実務の頭の使い方（どこを止めるか）とずれる懸念があり、設備単位で受け取る案を検討中。

- **作品名を MAAI（Minimum Approach Area Indicator、通称「間合い」）に決定。** 電気安全の用語 Minimum Approach Distance（最小接近距離）を下敷きにし、表示するのは距離ではなく領域なので Area とした。副題は「見えない間合いを、見えるように。」。リポジトリ名はフルネームとし、動画で「通称MAAI」と名乗って意味を説明する。
- オフラインモードの環境変数名を `LIVE_ENVELOPE_OFFLINE` から `MAAI_OFFLINE` に変更。契約の検証に `jsonschema` を依存に追加。アプリの API キーは `MAAI_ANTHROPIC_API_KEY` という別名で `.env` から読む（`ANTHROPIC_API_KEY` がシェルに漏れると Claude Code が API 課金に切り替わるため、名前ごと分ける）。
- **開発の安全柵を Claude Code の仕組みで作る。** 公開前チェック（禁止語・秘密情報・緯度経度・実図面形式）を git commit/push 前のフックと git の pre-commit の二重にかけ、`engine/` 編集後は pytest をフックで自動実行。禁止語の一覧はコミットせず、Claude Code の Read も禁止し、検出時も語を表示しない。
- **AR 位置合わせ検証を前倒し（11/4 夜、2〜3時間で打ち切り）。** AR はカメラで充電部を見つけるのではなく、計算済みの包絡を実物の位置に重ねるだけ。確かめるべきは位置合わせのずれで、合成レイアウトと屋外のテープ基準点で検証できる。実際の構内では撮影しない。
- **カメラによる設備・充電部の認識は作らない。** 課電しているかは見た目では決まらず、系統と開閉器状態から決めるしかない。加えて「画像解析ツール」は要項の避けるべき例に挙がっている。
- **題材を「充電部AR表示アプリ」から「図面→課電判定→安全包絡→重機干渉→Claudeの修正提案→承認」の机上ツールへ転換。** 当初案は Claude の役割が画像中の充電部候補の検出に偏り、汎用の画像解析ツールに見える。モバイル開発未経験で ARCore＋物体検出を6日で動かすのは、動かない・撮れないリスクが大きい。机上ツールなら Web と Python で閉じ、Claude の役割を「現場の判断の構造化と提案」に置ける。
- **安全判断は決定論、Claude は意味づけと提案。** 課電判定・距離・干渉は `engine/` が計算しテストで固める。Claude の提案は必ずエンジンで再検証し、採否は人が決める。
- **データはすべて合成。** 社内の図面・写真・情報は社外に出せない。接続する事業者名などを外部 AI に渡すことは電気事業法の行為規制にも関わりうるため、マスキング関門（許可リスト方式）を設計の中心に置く。
