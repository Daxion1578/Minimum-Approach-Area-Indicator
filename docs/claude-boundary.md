# Claude に任せること・任せないこと

MAAI は安全に関わる道具なので、どこを人と決定論コードが持ち、どこを Claude に任せるかを先に決めている。使い方を増やしたら1行足す。「なぜそれか」が書けない行は、使う理由が無いということなので消す。

## 任せない（決定論コードと人が持つ）

| こと | 持つ場所 | 理由 |
|---|---|---|
| 課電判定（どの導体が生きているか） | `engine/energize.py` | 系統の接続と開閉器の状態から一意に決まる。推論の余地を残すと事故になる |
| 距離・干渉・包絡の計算 | `engine/` | 幾何は計算で出る。LLM に数値を決めさせない |
| 停止ステップの適用 | `engine/steps.py` | 順序の誤りは接地と充電の衝突になる。エンジンが `invalid` で止める |
| 提案の採否 | 人 | 現場の責任は人にある。Claude の提案は必ずエンジンで再検証してから表示する |
| 外に出す情報の選別 | `agent/mask.py`（許可リスト） | 社内情報を外部に出せない現場で使える前提条件。決定論で動き、モデルを呼ばない |

## 任せる（Claude が持つ）

| こと | 場所 | なぜ Claude か |
|---|---|---|
| 現場を言葉で説明すると、構内モデルの下書きが立ち上がる | `agent/structure.py` | 図面や説明の意味づけは「人の読み方」の再現で、LLM が一番効く。下書きは必ず人が確認してから承認 |
| 作業指示の自然文から制約（止められない回線、作業対象、重機）を取り出す | `agent/structure.py` | 文面は人によって揺れる。構造化は LLM、適用はエンジン |
| 干渉したときの直し方を立案し、根拠を日本語で説明する | `agent/propose.py` | 候補の組み合わせは多く、現場の制約（止められない設備、納期）を踏まえた優先付けは判断の仕事。採否はエンジン検証と人 |
| 停止要否検討書の文章 | `agent/report.py` | 根拠の数値はエンジン、人に伝わる文章は Claude |

## 開発でどう使ったか（Claude Code）

| 仕組み | 何のため | なぜその仕組みか |
|---|---|---|
| `CLAUDE.md` | 変わらない約束（公開制約、安全設計の原則、報告の型） | 毎回のセッションで必ず読まれる唯一の場所 |
| Skill `/daily` `/wrap` | 朝と夜の決まった手順 | 本人が覚える操作を2つに絞る |
| Skill `/slice` `/verify` `/report` | 縦切りの計画、手元確認の手順、`STATUS.md` の更新 | 手順を人が毎回言い直すと抜ける。型として固定する |
| Skill `/critique` | 外部の目で批評し、足りないものを残す | 自分の作品は自分では客観視できない。批評をコミットすれば試行錯誤の記録になる |
| Skill `/publish-check` | 公開前点検 | 社内情報の混入は取り返しがつかない。人の記憶に頼らない |
| サブエージェント `safety-reviewer` | push・提出前の点検係（読み取り専用） | 書いた本人と同じ文脈では見落とす。別の文脈で独立に読ませる |
| サブエージェント `task-keeper` | `TASKS.md` の保守（残り・順序・落とす順） | 作業中の文脈に混ぜると、予定が実況に流される。別の係に持たせる |
| フック `pre_git_safety` | commit/push 前に禁止語・秘密情報・緯度経度・実図面形式を検出 | 人が忘れる作業は機械に。`--no-verify` も拒否 |
| フック `post_edit_tests` | `engine/` `contracts/` `tests/` 編集後に pytest を自動実行 | テストが落ちた状態で先に進ませない |
| worktree 並列 | 幾何／3D／エージェント層を別 worktree で同時に進める | 1人で複数の縦切りを並べる手段 |
| モデルの使い分け | 構造化は軽いモデル、提案は上位モデル（`.env` で差替え） | 遅延・精度・コストが用途で違う |
| MCP サーバ（検討中） | `agent/tools.py` を MCP として公開し、開発中の Claude Code と製品の提案ループが同じ道具を使う | 道具を一つにすると、開発中に見つけた不具合がそのまま製品の修正になる。採否は `docs/spec.md` §16 |
