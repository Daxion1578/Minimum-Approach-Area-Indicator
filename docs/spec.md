## 1. 一文と本質

人が減る現場で、止めきれない充電部との距離を、人の目だけに頼らない形にする。

本質（※仮）: 停止の段階ごとに変わる「近づけない領域」を、図面と停止手順から計算し、工事で動くすべてのもの（クレーン、吊り荷、搬入車両、仮置き資材、撤去品）に対して「その段階で、その空間は使えるか」に答える基盤。

- 3層で考える。下: 変わらない前提（図面・充電部の位置・電圧ごとの離隔）。中: 段階ごとに変わる近づけない領域（MAAI の核、`envelope.json`）。上: 工事で動くものについての問い（施工計画のたびに変わる）。
- 工程表（日付・人員・段取り）と配置図の作図は扱わない。停止の順番（第1段・第2段…）と、動くものの占める空間だけを受け取る。
- 価値が積み上がるのは中の層。一度作れば、次の問い・次の工事会社・AR・機械に同じ形で使い回せる。

## 2. 解く課題（Known）

- 変電所の更新工事は、運転中の構内で設備の一部を入れ替える。作業箇所の周りは停止するが、受電回線や母線は片側しか止められず、隣に充電部が残る。そこへクレーンが入ると、作業半径が充電部に近づく場所ができる。
- その危険は図面に描かれていない。系統の接続と開閉器の状態から計算して初めて分かり、停止ステップごとに変わる。空間に線は引けない。
- 今は担当者が、単線結線図を頭の中で課電・停止に塗り分け、配置図と作業半径を目で合わせ、停止申請の文面と突き合わせて決めている。人が減り経験者が替わると、この判断が再現できなくなる。
- 現場では専任監視者の目視に頼っており、目を離した一瞬が重大災害につながる。
- 設備は長く使われる（遮断器で40年前後、変圧器で60年近くが目安）。一つの変電所は数十年に何度も更新を受け、そのたびに図面と停止条件が変わる。道具とデータはそれより長く読める必要がある。

## 3. 使う人と場面（11/3 確定）

- 使う人: 電力会社の工事担当。自分で停止計画（どの開閉器を開け、どこに接地するか）を組み、工事会社の施工計画（クレーンの機種・据付位置）を確認する人。
- 場面: 工事の内容が決まった段階で、停止状態を道具の中で組み、その結果どの導体が充電のまま残るかを見て、クレーンが近づきすぎないかを確かめ、可・条件付き可・不可と根拠の図を出す。足りなければ追加停止か配置変更の案を受け取り、採否を決める。系統側の最終判断（停止の可否）は人が持つ。
- 入力: 手元の CAD から出した図面（ベクター PDF または DXF。結線図・配置図・断面図）、工事内容、施工計画。
- 今との差: 頭の中の塗り分けと目視の重ね合わせが、誰がやっても同じ結果になり、根拠が残る。保守的に取っていた予防停止を減らせる。
- 将来: 承認済みの包絡を現地の監視者（AR）と機械（クレーン側の装置）に届ける。今週は書き出しまで。
- 退けた案: 停止範囲を決まったものとして受け取るだけの側（実務の頭の使い方とずれる）、工事会社の施工計画担当（電力会社の図面を渡す前提が要る）。

  "site_id": "SITE-01",

  "nodes": [
    {"id": "LINE-A",  "kind": "source",      "voltage_kv": 66},
    {"id": "DS-A1",   "kind": "disconnector","voltage_kv": 66},
    {"id": "CB-A",    "kind": "breaker",     "voltage_kv": 66},
    {"id": "BUS-1",   "kind": "bus",         "voltage_kv": 66},
    {"id": "ES-B2",   "kind": "earthing",    "voltage_kv": 66, "attached_to": "DS-B2"},
    {"id": "TR-1",    "kind": "transformer", "windings": {"hv": {"voltage_kv": 66}, "lv": {"voltage_kv": 6.6}}}

  "edges": [
    {"from": "LINE-A", "to": "DS-A1", "conductor": "bare"},
    {"from": "DS-A1",  "to": "CB-A",  "conductor": "bare"},
    {"from": "CB-A",   "to": "BUS-1", "conductor": "bare"}

## 7. エンジン（決定論。Known。11/4 時点の実装に合わせて更新）

### 7.1 課電判定 `engine/energize.py`
- 閉じた開閉器と導体でつながる連結成分を求める。成分に `live` な電源が含まれれば `live`。含まれず、閉じた接地開閉器があれば `dead_grounded`、無ければ `dead_ungrounded`。`live` かつ接地あり → `invalid` としてエラー。
- 変圧器は巻線をまたいで伝播（両方向）。電圧階級はノード固有で、伝播で変わらない。
- 保守的既定: `treat_ungrounded_as_live = true`（未接地の停止区間は包絡計算では課電扱い）。設定で切替可。

### 7.2 幾何 `engine/geometry.py`
- すべてカプセル。線分と線分の最短距離（3D）を 1 関数で持ち、カプセル同士の隙間は `dist − r1 − r2`。
- テスト: 平行・交差・ねじれ・端点同士・退化（点）。

### 7.3 安全包絡 `engine/envelope.py`
- `live`（設定により `dead_ungrounded` も）な導体プリミティブごとに、半径 = 導体半径 + 離隔距離。
- 離隔表 `data/tables/clearance.csv`: 電圧階級 → 離隔（m）、出典列つき。既定値（`default-jp`）は一般送配電事業者が公開しているクレーン作業の目標値（100V/200V/6.6kV 2m、22kV 3m、66kV 4m、154kV 5m、275kV 7m、500kV 11m。法令の値ではない）で「要確認」。社により差があるので会社基準は表を差し替える。基発第759号の値（低圧 1.0m、高圧 1.2m、特別高圧 2.0m、60kV 超は 10kV ごとに 0.2m 加算）は比較用、労働安全衛生規則 第344条の接近限界距離は判定に使わない参考表として同じ CSV に持つ。
- 法的な枠組みの記述（README と画面の注記用）: 労働安全衛生規則 第349条（充電電路に近接する場所でのクレーン等の作業）。

### 7.4 重機 `engine/crane.py`
- ベース位置、車体の向き、ブーム長、起伏角、旋回角の範囲、フック垂下、吊荷の寸法。旋回角を 5° 刻み（`data/rules/clearance_rules.json`）で掃引し、各姿勢でブーム・ロープ・吊荷・車体のカプセルを生成。
- 諸元は 25t 級ラフテレーンの例示値（コード内の `spec`）。「例示値」と明記。

### 7.5 離隔判定 `engine/clearance.py`
- 旋回は 2° 刻みで、刻みの間の動きを含むようにブーム・ロープ・吊荷の半径に「ブーム長 × sin(刻み/2)」を足す（刻みの間の見落としを出さない）。起伏角が 2 つ（吊る点と置く点）あれば両方で掃引する。
- 全姿勢 × 全包絡の最短距離を計算し、導体ごと相ごとの最小距離・必要距離・余裕を返す。判定は `ok` / `conditional`（余裕が `margin_m` 未満。監視員と旋回限界の印を条件にする、R6）/ `ng`、根拠の文（R1/R2）つき。
- 出力はそのまま画面の `clearance` と承認の `plan.json` に入る。

### 7.6 作業日の停止範囲 `engine/steps.py`（11/6 に「停止ステップ」から変更）
- 原則: 作業する機器に電気が流れ込む端すべてで電気を断つ。対象の端子ごとに流入の道を外へたどり、最初に出会う断路器（目に見える切れ目）まで、途中の遮断器も含めて切る（遮断器が対象なら両隣の断路器、線路側断路器なら構内側は遮断器と母線側断路器）。
- 送電線（構外）に出る道は、相手端の遮断器・断路器を切ることを「相手端の条件」として書き出し、その電源を停電として扱う。止めない母線に開閉器を挟まず行き当たる端は「端子の切り離し」を条件に書き、母線は充電のまま。
- 変圧器が対象のときは、変圧器専用のベイ（遮断器が 1 台のベイ）を母線の手前まで止める（遮断器と母線側断路器も切る）。ほかの回線と遮断器を共有するベイ（1・1/2 母線）は変圧器の隣の断路器で止める（11/6 本人）。
- 切り離された作業対象以外は平常どおり運用（最小の停止範囲）。出力は 1 段の `state` と、切る機器・条件・停電区間。接地は流入端すべてに取る前提で、条件の先頭に書く。
- 停止範囲を広げるのは、クレーンを置けないときだけ（§7.7・§7.9）。止めるかどうかは人が決める。

### 7.7 修正案の候補 `engine/propose.py`
- 不可／条件付き可のとき、ベース移動（4 方向 × 2/4/6m）、旋回範囲の制限、起伏角の増加、最寄りの充電機器の追加停止（§7.6 で生成）を候補にし、一つずつ §7.5 で再判定して、可 → 条件付き可 → 不可の順に並べる。
- Claude は候補を作らない（§8.3）。

### 7.9 重機の選定 `engine/crane_select.py`（11/6 追加）
- 入力: 吊る点（更新設備の位置。高さは機器の高さ＋吊具）、置く点（資材置場）、吊る重さ（機器の例示値、画面で書き換え可）、作業日の停止状態。
- クラス（13t・16t・25t・50t 級。荷重表は例示値で「要確認」、`data/tables/cranes.json`）を小さい順に試す。構内を 2m の網目で据付位置を試し、機器の基礎・鉄構から外れ、2 点に届き、作業半径での定格荷重が吊る重さ＋フック以上で、2 点の間の旋回（短い方の円弧、両端の起伏角の両方）で充電部の離隔を保てる位置を探す。
- 答え: 全部を満たす一番小さいクラスと、その中で余裕が最大の位置。一つ下のクラスが使えない理由（届かない・重さ超過・離隔不足と導体名）。どのクラスでも置けないときは、邪魔をしている充電部の追加停止（§7.6 の規則）で再計算し、「止めれば何級で置けるか」を出す。

### 7.8 承認と書き出し `server/app.py` + `synth/step_drawings.py`
- 重機の配置が無い計画は承認しない。承認ハッシュには、結線・配置・離隔表の内容のハッシュを含める（どの版で判定したかを残す）。
- 承認時に判定をやり直し、`ng` と `invalid` は拒否。`data/sites/<site>/approved/plan-<相対時刻>/` に `plan.json`（承認ハッシュ）、`envelope.json`（§6.5）、`steps.json`、段階ごとに塗り分けた単線結線図 `step-N-sld.pdf` を書き出す。暦日は入れない。
- glTF 書き出しは「この先」。

## 8. Claude 層（Known。11/4 時点の実装に合わせて更新）

### 8.1 境界
| Claude に任せる | 任せない |
|---|---|
| 取り込んだ図面の意味づけ：開閉器の種別の確認、名前の無い導体の説明、人に確かめてほしい点の文章 | 図面からの接続の読み取り、課電判定、離隔の値、距離計算、干渉判定、ステップの生成と適用、修正案の候補づくりと再判定 |
| 修正案の説明：候補ごとに何を変え、何が良くなり、何を犠牲にするか。順位づけの理由 | 提案の採否（エンジン検証＋人）、承認（人） |

`docs/claude-boundary.md` が一覧。作っていないもの（作業指示の自然文からの制約抽出、停止要否検討書の文章）は「この先」。

### 8.2 図面取込 `ingest/pdf_sld.py` → `agent/structure.py`
1. `ingest/pdf_sld.py` がベクター PDF から主回路の線（太さで判別、破線＝未設は除く）、開閉器記号の位置、記号の右の番号（文字）を取り出し、交点でまとめて導体ネットにし、記号の位置でネットを切り、番号で結んで候補グラフを作る。接地開閉器は補助線の端点で付け先を決める。
2. 候補グラフ（名前は `agent/mask.py` で符号化）を Claude に渡し、種別の確認・ネットの説明・質問を返させる。規則（番号の形）と食い違う種別は上書きせず質問にする。呼べないときは規則だけで同じ形を返す。
3. 画面で「未確認」→「確認済」。精度は `scripts/run_eval.py`（§11）。
- 対象はベクター PDF。スキャン画像は対象外（README に明記）。DXF は「この先」。

### 8.3 修正案の説明 `agent/explain.py`
- 入力: 判定結果と、§7.7 が作って再判定した候補（判定値つき）。出力: 候補ごとの説明と順位づけの理由。数値は入力のまま使い、新しい数値を作らせない。追加停止には「停止調整が要る」を添えさせる。
- 画面は engine の判定値を先に出し、説明は後から差し込む。呼べないときは定型文。

### 8.4 モデルと動作モード `agent/client.py`
- 意味づけ（`MAAI_MODEL_STRUCTURE`）と説明（`MAAI_MODEL_PROPOSE`）で別のモデルを指定できる。既定は同じ。
- `MAAI_OFFLINE=1` またはキー無しで呼ばず、`available()` が False を返す。呼び出し側が規則で代替する。
- 素のメッセージ API（JSON を渡して JSON を受け取る）。ツール呼び出しループや Managed Agents は使っていない。

### 8.5 マスキングと記録 `agent/mask.py`, `agent/client.py`
- 置換表方式: 線路名・変電所名・地名（「〜線」「〜変電所」「〜町」など）を LINE-n / SITE-n / PLACE-n に置き換え、戻すのはローカル。母線・線路側などの一般語は残す。
- 容量類・暦日・座標（緯度経度）はそもそもデータに持たない（§12）。構内ローカル座標と判定の数値は送ってよい。
- 送信ごとに `logs/outbound/<時刻>-<目的>.request.json` / `.response.txt` を残す（git 管理外）。

## 9. 画面（Known。単一HTMLアプリ、タブ＝導線。11/6 に作業日の停止範囲と重機の選定へ更新）

上の帯が、次に押すものを示す。

4. 計画確定: 対象・切る機器・追加停止・クレーン・判定と、承認の条件（接地、相手端、端子の切り離し、追加停止の調整）→ 承認でハッシュ付与 → 停止範囲図（PDF）・計画・包絡の書き出し。
