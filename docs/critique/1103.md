## 公開ルール上のリスク

- `proto/FREEZE.md` 3行目に「ハッカソン期間中」。`docs/spec.md` §12（301行目）に「ハッカソンの全データは」。作品の文章から外す約束（`CLAUDE.md`）に反する。`proto/` は消す予定でも、消すまで公開されている
- `README.md` 冒頭の「Built with Claude: Japan 2026 提出作品」。禁止語ではないが、「この文がなくても同じ文章になる」の約束からは外れる。開発期間の明示だけ残して提出先は README から外すか、末尾に移す
- `proto/FREEZE.md` と `docs/claude-boundary.md` の内容が、11/3 の決定と食い違う。FREEZE は「DXF 読み取り・提案の自動化を作らない」、boundary は「現場を言葉で説明すると下書きが立ち上がる」を Claude の必須の瞬間に置く。11/3 の決定は「言葉で語る方式は作らない。PDF 投げ込み」。初見の人は、どれが現在の設計か分からない
- `docs/claude-boundary.md` の「開発でどう使ったか」に「worktree 並列」「モデルの使い分け」があるが、`git log` にも設定にも痕跡がない。使っていない仕組みを「使った」と書くと、使った仕組みまで疑われる
- 禁止語リスト `.forbidden-terms.local.txt` が空。公開前チェックは今のところ秘密情報・座標・図面形式しか見ていない。push 済みのコミット17件は検査なしで公開済み
- 合成サイトの線路名が Opus / Fable / Sonnet / Haiku / Mythos（`docs/decisions.md` 11/3）。初見の AI 業界の人間には「模型のおもちゃ」に見える。実務の流儀（方面名・番号）に寄せる方が作品の真剣さが伝わる
- three.js r160 を `web/vendor/` に同梱（MIT、LICENSE あり）。既存コード持ち込みの禁止は自作コードの話で、これは問題ない。README の謝辞に一行あると安心

## 足りないもの（軸ごとに3つ。動画で見えるようになる直し方を添える）

### 課題の切実さ
1. 数字が無い。「予防停止が年に n 件、1件の調整に m 時間」のような、作者にしか出せない数字を README 冒頭と動画 0:00–0:30 に一つ。概数で、出所は「自分の経験」でよい
2. 「使い続ける人」が §3 の一文で止まっている。工事担当が、工事のどの週に、何を手に持ってこの画面を開くかを一段落で。動画の 1:00 の入り方になる
3. 「今との差」の最後の一文（予防停止を減らせる）が、作品の売りなのに埋もれている。動画の山場は「赤が消える」より「保守的に止めていた一区間を止めずに済む」の方が強い

### 伝わり方
1. README の5段階と判断記録の入口（PDF 投げ込み）を一致させる。README の「図面取込」を「ベクター PDF / DXF」に直す。スキャン画像は対象外の一文も README に（決定済みだが未反映）
2. 動く画面の絵が一枚もない。`web/prototype.html` の3D を `docs/img/` に一枚置き README に貼る。「開発中」の注記があっても、絵があるだけで理解が3倍速い
3. `docs/demo-plan.md` の 1:00–2:15 が「操作の流れを通しで」の一行。各ステップで画面に何が映り、何を押すかを一行ずつに割る。実装の優先順位がここから決まる

### Claude の役割
1. Claude が呼ばれる瞬間がまだ一つも動いていない。縦切り3（11/5）まで待つと、動画収録の2日前まで Claude ゼロ。提案ループ（干渉→提案→再検証）の往復ログを、エンジンが無くても試作画面の JSON で一度回してみる価値がある
2. 「Claude が無ければ成立しない瞬間」が文書上で三つ（図面の意味づけ、提案、検討書の文章）に分散している。動画で見せる一つに絞る。提案ループが最も「再検証して通るまで」という安全設計を同時に見せられる
3. `docs/claude-boundary.md` を現在の決定に合わせて書き直す（言葉で語る方式を消す、未使用の仕組みを消す）。この文書は「なぜ Claude か」を一番よく語っている。食い違いが残ると価値が下がる

### 作り込み
1. 本番に残るコードがゼロ。`contracts/` と `engine/energize.py` を今日中に通す。これが無いと「判断は決定論」という設計原則が文章でしかない
2. `proto/` を移植後に消す約束だが、消すまで「契約が二つある」リポジトリに見える。移植が終わった時点で同じコミットで消す
3. `README.md` に「開発中。下の機能は計画で」とあるが、どれが動いてどれが計画かの印がない。各段階の行頭に「動く／計画」の印を付け、縦切りが終わるたびに更新する
